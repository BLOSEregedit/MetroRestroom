# 个人中心设计说明

## 1. 设计目标

个人中心的定位不是“强登录入口”，而是小程序的能力补充区和轻量运营区。  
核心思路是：**急用时不添乱，闲时有趣味**。

首页继续保持工具效率和高级感，优先承载查厕所、定位、站点拨轮、搜索、路线等高频能力；与身份、偏好、记录、趣味相关的内容，统一收敛到个人中心。

## 2. 登录策略

小程序核心功能无需登录，未登录用户也可以直接使用以下能力：

- 查厕所
- 定位
- 站点拨轮
- 搜索
- 查看路线
- 设置声音/震动
- 查看最近记录

个人中心提供清晰的选择，而不是强制拦截：

- 用户可以选择登录
- 用户也可以选择不登录继续使用

登录的价值主要体现在个人化能力与长期沉淀，而不是基础使用门槛。

## 3. 登录后能力

登录后，个人中心可承载以下能力：

- 收藏站点
- 点赞厕所信息
- 反馈纠错
- 打卡记录
- 个人统计

这些能力用于增强用户留存、提升数据质量，并形成个人使用习惯的沉淀。

## 4. 声音与震动设置

声音与震动属于高频交互偏好，建议在个人中心提供独立开关。

建议策略如下：

- 拨轮音效默认开启
- 震动默认开启
- 个人中心支持独立开关
- 声音允许用户手动关闭
- 声音策略应尽量尊重系统静音状态，避免打扰

这里的原则是：交互反馈要明确，但不能制造噪音负担。

## 5. 趣味玩法方向

个人中心可以承接“使用痕迹”和“轻社交感”的趣味内容，但第一版要控制表达方式，避免过度娱乐化。

可考虑的方向：

- 如厕足迹
- 常去站点
- 救急次数
- 打卡

关于排行榜类玩法：

- “拉屎排行榜”或“蹲点排行榜”可以作为趣味方向讨论
- 第一版建议优先做个人统计，或仅做匿名/好友范围内的轻量展示
- 不建议第一版做强公开排行榜

原因是公开排行榜容易带来以下问题：

- 低俗化风险
- 隐私暴露风险
- 刷榜和作弊风险

## 6. 产品原则

个人中心的设计原则如下：

- 不为了查厕所强制登录
- 首页保持工具效率，不被趣味内容打扰
- 趣味内容放在个人中心，作为增值体验
- 统计和荣誉感要克制，避免喧宾夺主
- 兼顾真实使用场景和长期留存

## 7. 第一版建议范围

建议第一版优先落地以下内容：

- 登录/不登录的清晰选择
- 收藏、点赞、纠错、打卡
- 个人统计
- 声音与震动独立开关
- 最近记录保留

暂不建议第一版重点投入：

- 强公开排行榜
- 复杂好友体系
- 过度游戏化的成就体系

## 8. 结论

个人中心的价值在于补齐“身份、偏好、记录、趣味”四类能力，但不能影响主流程。  
整体策略应保持克制，让小程序在“急用”时足够快，在“闲时”时也有一点可玩性。
