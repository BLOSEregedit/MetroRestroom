# ETA V2 实施任务

本清单区分“本轮本地实现”和“后续受控 CloudBase 发布”。只有完成并验证的项目才能勾选；云端集合、权限、数据写入和部署必须另行确认。

## 阶段 1：规范与模板

- [x] 1.1 建立一城一工作簿的空白采集模板
  - 建立统一工作表、字段字典、枚举和示例。
  - 为每个字段标记 `owner_required`、`online_research`、`onsite_required` 或 `derived`。
  - 允许待采集字段留空，以状态列表示缺失原因。
  - _需求：R9_

- [ ] 1.2 定义稳定 ID 与兼容映射
  - 为城市、线路、物理站、线路站、路径、方向、换乘、卫生间和来源定义不可变 ID。
  - 建立上海旧 `lineStationId`／`restroomId` 到新 ID 的映射。
  - 禁止使用 Excel 行号或显示顺序生成持久业务主键。
  - _需求：R5、R9_

- [ ] 1.3 实现本地 Excel 导入与质量报告
  - 校验工作表、字段类型、枚举、主外键、来源和核实状态。
  - 输出缺失、冲突、待线上整理和待实地核实清单。
  - 保留原始位置描述，不覆盖 legacy Excel。
  - _需求：R3、R9_

## 阶段 2：上海数据迁移

- [ ] 2.1 迁移 core 数据
  - 把现有线路、物理站、线路站、路径、方向、别名、环线、支线和换乘例外转为规范数据。
  - 对账现有线路、路径、active 线路站和物理站数量。
  - _需求：R5、R6、R9_

- [ ] 2.2 迁移 detail 数据
  - 把现有卫生间原文迁移为独立设施和线路站关联。
  - 同站跨线记录先保留为独立候选，不在没有证据时自动合并。
  - 导入入口数据并保留 OSM 来源和歧义状态。
  - _需求：R5、R9_

- [ ] 2.3 整理 ETA 基础数据
  - 从官方公开资料整理相邻站有向时分和常规运营间隔。
  - 记录 `official`、`timetable_derived`、`public_verified` 或降级方法。
  - 生成尚需实地核实的换乘和卫生间步行时间清单。
  - _需求：R3、R4_

## 阶段 3：本地 ETA V2

- [x] 3.1 实现秒级有向图
  - 将列车区间、可选的起点换向步行、跨线换乘、同线换车和卫生间步行建模为不同边。
  - 起点换向步行没有核实数据时固定为 `0`；移除旧版 `reverseAtOrigin 4—6 分钟` 范围。
  - 支持普通线、环线和支线路径。
  - _需求：R2、R5_

- [x] 3.2 实现单值公式和固定降级顺序
  - 使用典型间隔一半计算首次候车及换乘后的期望候车；无需乘车的同站目标不计候车。
  - 所有秒数求和后只舍入一次：小于 10 分钟取最近 1 分钟，10—30 分钟取最近 2 分钟，大于 30 分钟取最近 5 分钟，输出 `约 X 分钟`。
  - 缺失边按同线资料、线路中位数和全局兼容值依次降级。
  - _需求：R1、R3、R4_

- [x] 3.3 接入现有页面数据契约
  - 保持首页卡片、抽屉、最近记录和纠错上下文现有结构。
  - 移除用户可见的 ETA min/max 区间，不增加置信度标签。
  - 不远程加载任何 UI 或业务代码。
  - _需求：R1、R6_

- [x] 3.4 增加 ETA 回归
  - 覆盖同站、反方向、环线闭环、支线直达／换车和跨线换乘。
  - 覆盖首次期望候车只计一次、无需乘车不计候车、10／30 分钟分段边界、1／2／5 分钟刻度的半刻度向上边界和每一级降级。
  - 覆盖普通线路锚点另一侧只使用目标方向首次平均候车，未核实换向步行时不增加固定惩罚；4 号线严格遵循用户选定内／外圈。
  - 对代表性长路径确认结果不再产生宽区间。
  - _需求：R1、R2、R4、R5_

## 阶段 4：本地数据版本与回退

- [ ] 4.1 定义代码包完整基线格式
  - 逻辑区分 `core`、`detail`、`eta`、`status`。
  - `<= 256 KB raw` 的城市默认生成单个 `city-data` part；上海约 `607 KB raw` 保持一个城市批次，可使用多个 part，但不得逐线拆分。
  - 固化工程阈值：`<= 256 KB raw` 单 part，`256—700 KB raw` 城市批量且 part 控制在 `128—256 KB raw`，`> 700 KB raw` 拆分，单模块 `> 512 KB raw` 改版本化文件或分页。
  - 用上海现有 `540,331 B raw / 59,549 B gzip` 与 ETA 预计 `66,610 B raw / 6,046 B gzip` 校验发布单元；对比逐线路拆分约 `711 KB raw / 91 KB gzip`。
  - _需求：R6、R7_

- [ ] 4.2 实现候选缓存和 `activeVersion`
  - 候选版本与当前有效版本隔离存储。
  - 完成 schema、哈希、引用和数量校验后原子切换。
  - 失败继续使用旧缓存或代码包基线。
  - _需求：R6、R8_

- [ ] 4.3 增加离线与失败回归
  - 模拟无云能力、请求失败、快照缺失、哈希错误、schema 不兼容和本地写入失败。
  - 确认所有情况都不会破坏现有上海完整查询。
  - 检查云函数响应 `1 MB`、单代码包 `2 MB`、全部分包 `30 MB`、本地缓存 `10 MB` 和并发请求 `10` 的平台边界；阈值测试不得把平台上限误写成推荐值。
  - _需求：R6、R8_

- [ ] 6.2 建立 staging 导入与发布清单

- [ ] 6.3 部署并验证 V2 数据读取接口

  - _需求：R6—R10_
