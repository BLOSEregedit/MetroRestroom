# 首页交互密度与线路切换需求

状态：第二轮调整本地实现完成，待真机验收

## 1. 问题与范围

首页需要在地铁弱网和单手操作场景下，用稳定的信息密度同时表达当前计算起点、派生目标站、线路方向、换乘入口和厕所信息。本轮恢复最初确认的苹果式视觉和原字号，并以用户第二轮确认明确覆盖上一轮“圆点纯视觉、不可点击”的规则。本规格只收口首页线路拨轮、顶部控制区、换乘提示和多厕所抽屉；不修改路径、ETA、云端同步或纠错审核协议。

## 2. 术语

- **计算起点**：系统定位站或用户通过顶部“更换”入口选择的手动锚点站。
- **派生目标站**：当前停在拨轮中心、右侧卡片处于高亮状态的站点。
- **当前物理站**：跨线路共享的真实车站；同一物理站可对应多个线路站点 ID。
- **展示序列**：按当前线路、运行路径和方向生成的有序站点列表。
- **当前线路**：首页当前正在浏览的线路上下文。

## 3. 用户故事与验收标准

### 需求 1：高密度线路拨轮

**用户故事：** 作为正在地铁中快速查询的用户，我希望一屏看到足够多的相邻站点，同时能立刻辨认当前目标站。

1. 当首页使用正常系统字号并进入站点浏览状态时，系统应在主体可视区域固定同时展示 5 个站点行。
2. 当用户上下滑动站点时，系统应保持左侧轨道为固定在左侧栏、贯穿可视区域的连续轨道，不因卡片高亮而断开、缩放或改变选中样式。
3. 当某站吸附到拨轮中心时，系统应只高亮该站右侧卡片；左侧定位针和圆点只表达定位或起点操作，不得同步承担中心卡片高亮。
4. 当列表包含有厕所、无厕所和数据异常站点时，系统应保持站点行对齐，避免因卡片类型不同破坏轨道连续性。
5. 当页面调整为一屏 5 站时，系统应保持最初确认的正文、站名和辅助文字字号，通过缩小站点行间距、卡片内边距和区块间距获得密度，不得通过缩小字体实现。

### 需求 2：显式计算起点

**用户故事：** 作为用户，我希望始终知道预计耗时从哪里开始计算，并通过明确按钮更换起点。

1. 当首页展示顶部控制区时，系统应显式显示“当前计算起点”和站名，并提供可点击的“更换”入口。
2. 当用户点击“更换”时，系统应打开站点选择流程；确认后才更新计算起点。
3. 当系统取得智能定位站时，系统应在该站左侧显示定位针，并保持它只表达当前定位站。
4. 当用户点击智能定位站之外的任一站点圆点时，系统应将该站锁定为手动计算起点，保持当前派生目标站和线路不变，并同步更新顶部起点文案。
5. 当用户点击“更换”时，系统应继续提供完整站点选择流程；圆点点击是同一手动起点能力的快捷入口，不得形成第二套起点状态。
6. 当定位、方向、线路或拨轮位置变化时，系统应保持顶部计算起点文案与实际 ETA 起点一致；手动起点锁定后，定位变化不得覆盖它。

### 需求 3：派生目标站

**用户故事：** 作为用户，我希望滑到某站就看到从固定起点到该站厕所的结果，又不误改起点。

1. 当站点卡片吸附到拨轮中心时，系统应将该站设为当前查询的派生目标站，并据此更新路径、同步线路范围和到厕耗时。
2. 当派生目标站变化时，系统不得反向修改系统定位站或手动锚点站。
3. 当首页未提供独立目标站选择器时，系统应以拨轮中心站作为唯一派生目标，不得把中心站降级为纯视觉状态。

### 需求 4：方向切换与调头判定

**用户故事：** 作为用户，我希望切换方向时仍停留在刚才查看的站点，并理解当前目标是否需要调头。

1. 当用户切换普通线路方向或环线圈向时，系统应保持当前物理站和计算起点不变，只反转当前展示序列，并重新计算卡片耗时。
2. 当方向切换完成时，系统应让同一物理站继续停留在拨轮中心，不得跳回默认站、定位站或线路首站。
3. 当计算起点和派生目标站都位于切换后的展示序列中时，系统应以切换后序列的索引判定调头：`targetIndex < originIndex` 时标记需要调头，否则不得仅因方向切换标记调头。
4. 当当前高亮卡片需要调头时，系统应只在该高亮卡片中显示克制的调头图标或“需调头”短提示；非高亮卡片不得重复显示调头提示。
5. 当计算起点不属于当前展示线路时，系统应继续使用本地跨线路径结果判定耗时和方向语义，不得伪造当前线路索引。

### 需求 5：可发现的换乘切线

**用户故事：** 作为身处换乘站的用户，我希望既可以横滑切线，也能看到并点击明确的换乘线路入口。

1. 当派生目标站是换乘站时，系统应在右侧显示半透明的换乘提示，并展示全部可切换线路的可点击胶囊。
2. 当换乘站包含多条可换乘线路时，系统不得只提供隐藏横滑手势、单个“更多”计数或不可点击提示来代替线路胶囊。
3. 当用户横滑或点击线路胶囊切换线路时，系统应保持同一物理站为派生目标站，并保持计算起点不变。
4. 当线路切换完成时，系统应更新线路上下文、展示序列、方向文案、线路标识和 ETA，但不得写入新的计算起点。
5. 当当前站不是换乘站时，系统不得显示无效的换乘提示或线路胶囊。

### 需求 6：多厕所抽屉与反馈入口

**用户故事：** 作为在换乘大站找厕所的用户，我希望按线路快速区分多个厕所，同时不被醒目的纠错按钮干扰主查询。

1. 当主列表展示任意站点卡片时，系统不得显示红色“纠错”或同等强度的反馈入口。
2. 当用户打开厕所抽屉时，系统应按厕所所属线路分组展示；当前线路分组应排在最前，其余线路按项目既有线路顺序排列。
3. 当某组包含一个或多个厕所时，系统应在组标题显示线路标识，并在组内逐条展示对应厕所信息，不得把不同线路厕所混成无分组列表。
4. 当抽屉展示反馈入口时，系统应使用低强调度文字入口，并自动带入当前线路、物理站和厕所记录；反馈入口不得使用品牌红色主按钮样式。
5. 当用户关闭抽屉时，系统应保留当前线路、方向、派生目标站和计算起点。

### 需求 7：线路色与正文层级

**用户故事：** 作为用户，我希望线路身份清楚，但正文仍保持工具类产品的稳定可读性。

1. 当页面展示官方线路色时，系统应仅将其用于轨道、圆点、线路胶囊、线路组标题等线路标识。
2. 当页面展示站名、位置、预计耗时、状态原因或反馈文案时，系统应使用黑灰正文层级，不得用整张线路色卡片或大面积线路色正文表达线路身份。
3. 当右侧卡片高亮时，系统应通过大圆角卡片、柔和阴影、明度或轻微缩放表达焦点，不得让左侧轨道、定位针或圆点同时表达中心高亮。
4. 当首页展示顶部控制卡、站点卡和厕所抽屉时，系统应保持最初确认的苹果式白灰界面、大圆角、柔和阴影和原有字号，不得改成工业硬边、紧缩字体或高对比装饰风格。

## 4. 非目标

- 本轮不新增独立目标站选择器。
- 本轮不修改地铁拓扑、路径权重、ETA 常量和云端同步协议。
- 本轮不把反馈入口完全移除；只从主列表移入厕所抽屉并降低视觉权重。
- 本轮不使用线路色表达推荐、可用性或数据同步状态。
