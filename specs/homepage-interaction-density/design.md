# 首页交互密度与线路切换设计

状态：第二轮调整本地实现完成，待真机验收

## 1. 设计规格

1. **目的**：让用户在地铁弱网、单手操作和短时查看场景下，一屏稳定读取 5 个站点，并明确区分计算起点、智能定位站与拨轮派生目标。首页优先保证查询效率、换乘可发现性和信息可信度。
2. **美学方向**：Luxury／refined（原生苹果式柔和工具感）。恢复最初确认的大圆角、白灰层级、柔和阴影和克制动效，不采用工业硬边或压缩字体的高密度方案。
3. **颜色**：正文 `#1F2429`、次级文字 `#6F7780`、页面底色 `#F6F7F8`、卡片 `#FFFFFF`、分隔线 `#D8DDE1`；品牌红 `#D84A4A` 仅用于 Logo 等品牌位置；各线路使用项目已有官方线路色，但只用于线路标识。
4. **字体**：微信原生小程序中文界面使用 `PingFang SC`，并以 `Hiragino Sans GB`、`Microsoft YaHei` 作为平台回退。工具数字与时间保持同一无衬线字族，不引入网络字体。
5. **布局**：非对称双栏。左侧窄栏为固定连续轨道、智能定位针和可点击站点圆点，右侧宽栏承载固定 5 站的圆角卡片；换乘提示从右边缘半透明露出，线路胶囊进入可点击区域。项目既有苹果风、品牌和原生小程序性能约束优先于通用 Web 视觉模板。

## 2. 信息架构

```text
吸顶控制区
├─ 城市与当前线路
├─ 当前计算起点：站名 / 更换
└─ 当前方向 / 切换方向 / 定位模式

同步状态条

站点拨轮
├─ 左侧固定连续轨道
│  ├─ 智能定位站定位针
│  └─ 可点击站点圆点
└─ 右侧站点卡片
   ├─ 派生目标卡片高亮
   ├─ 换乘提示与线路胶囊
   └─ 查看全部厕所

厕所抽屉
├─ 当前线路分组
├─ 其他线路分组
└─ 弱化反馈入口
```

## 3. 状态模型

首页保留以下相互独立的状态：

- `originStationId`：计算起点，只能由定位、恢复智能定位或顶部“更换”流程更新。
- `targetStationId`：派生目标，对应当前吸附到中心的物理站。
- `lineId`：当前浏览线路。
- `direction`／`routeId`：当前方向和支线运行路径。
- `displayedStations`：依据线路、路径和方向生成的展示序列。
- `currentIndex`：派生目标在展示序列中的位置。

智能定位站的定位针只表达 `systemOriginStationId`。其他站点圆点复用手动起点动作：点击后更新 `originStationId` 并进入手动锚点模式；站点吸附仍只更新 `targetStationId` 和 `currentIndex`，不得更新 `originStationId`。

## 4. 站点拨轮布局

- 主体可视区固定展示 5 个站点行；保留最初确认的站名、正文和辅助文字字号，只压缩站点行间距、卡片内边距与区块间距。
- 左侧轨道作为贯穿可视区的独立背景层，保持固定宽度和连续线段。智能定位站使用定位针；其他站点使用可点击圆点，点击后锁定为手动计算起点并同步顶部文案。
- 右侧卡片是唯一浏览焦点载体。卡片保留大圆角和柔和阴影；非中心卡片保持稳定尺寸和正常可读性，中心卡片可以使用 `1.02—1.04` 轻微缩放、明度或柔影增强。
- 有厕所、无厕所和数据异常卡片可以使用不同内容高度，但每一站的轨道刻度必须与对应卡片中心对齐，轨道不得因卡片类型出现断点。

## 5. 顶部计算起点

顶部第二层使用显式结构：

```text
当前计算起点
人民广场站                     更换
```

- “更换”是唯一常驻手动设置起点入口，点击后复用现有站点选择器。
- 选择器确认前保持原起点；取消选择不写入状态。
- 定位模式或手动锚点说明可以保留在下一行，但不能代替“当前计算起点”标签和站名。

## 6. 方向切换

方向切换使用“保持实体、重建序列”的方式：

1. 在切换前保存当前 `originStationId`、目标物理站 ID 和当前线路。
2. 反转方向并重建 `displayedStations`。
3. 通过目标物理站 ID 找到切换后对应线路站点，恢复到中心位置。
4. 保持 `originStationId` 不变，重新计算路径、ETA 和同步线路范围。
5. 当起点和目标都在切换后的当前展示序列中时，计算 `originIndex` 与 `targetIndex`；仅当 `targetIndex < originIndex` 时标记“需调头”。

如果起点不属于当前线路，调头与 ETA 继续使用本地跨线路径结果，不能以缺失索引代替路径判断。

调头提示只渲染在当前高亮卡片：优先使用与现有图标体系一致的克制图标，空间不足时使用“需调头”短文案。非高亮卡片即使路径结果需要调头，也不重复展示提示。

## 7. 换乘切线

- 换乘站右侧显示半透明提示层，提示层不覆盖主要厕所正文，也不抢占纵向滚动。
- 提示层内直接列出全部可切换线路胶囊；胶囊显示线路号／名称，使用对应官方线路色作为小面积标识。
- 横滑与点击胶囊调用同一切线动作，确保两种入口的状态结果一致。
- 切线前保存目标物理站和计算起点；切线后按同一物理站映射到新线路站点，并将其保持在中心。
- 多线换乘不使用仅靠手势、仅显示“+N”或不可点击虚线轨道的方案。半透明提示负责暗示，线路胶囊负责显式操作。

## 8. 多厕所抽屉

抽屉数据先按 `lineId` 分组，再排序：

1. 当前线路分组置顶。
2. 其余分组按项目线路排序规则排列。
3. 分组内保持稳定的源数据顺序；没有距离依据时不宣称“最近”。

组标题由小面积线路色标识和线路名称组成；厕所位置、闸内外、设施、ETA、状态原因统一使用黑灰正文。每条厕所信息底部可显示“信息有误？反馈”弱链接，点击后带入该条厕所上下文。主列表不再出现反馈入口。

## 9. 模块边界

- 目录数据层继续提供物理站映射、线路顺序、展示序列和厕所所属线路。
- 首页页面层维护起点、派生目标、方向、换乘提示和抽屉开关。
- 反馈页继续复用既有纠错提交链路；本轮只改变入口位置和视觉权重。
- 云端同步、状态覆盖和 ETA 均沿用现有接口；本轮不增加云函数调用。

## 10. 验证策略

- 状态单测：验证吸附不改起点、圆点锁定手动起点、智能定位针语义、方向切换保持实体、调头索引规则和切线保持物理站。
- 数据测试：验证多线路厕所分组、当前线优先、其余线路稳定排序。
- 页面交互测试：验证智能定位站显示定位针、其他圆点可锁定手动起点、换乘胶囊可点、横滑与点击结果一致、主列表无反馈入口。
- 视觉验收：在代表性 iOS／Android 视口检查一屏固定 5 站、原字号、大圆角柔影、轨道连续、只有右卡承担浏览高亮、调头提示仅在高亮卡、线路色使用范围和抽屉正文对比度。
- 回归测试：验证弱网、本地查询、同步状态、定位、支线和环线能力不受影响。
